1. 총평

진짜 production급 end-to-end 동작 엔진 — 프로토타입이 아니다. ~181K LOC의 Rust Half-Edge DCEL 커널(2844 테스트 통과)이 실제 3.6MB WASM 바이너리로 컴파일돼, ~101K LOC의 TypeScript/Three.js 웹앱이 7,148줄 WasmBridge(engine call site 303개)를 통해 구동한다. + MCP 서버 패키지가 커널을 AI 에이전트에 노출.

성숙도는 불균등하지만 정직하다: 시맨틱 레이어(axia-core)·WASM 브리지·도구 레이어·렌더/스냅/재료는 조밀한 테스트와 거의 0에 가까운 스텁으로 production급이고, DCEL 커널은 강력한 불변식/manifold 검증 시스템을 실제 release gate로 배선한 mostly-working 상태다. 규율이 예외적: ADR 번호 추적 336건, additive-only API baseline, no-#[ignore] 정책, phantom-tool 갭을 스스로 잡아 고친 자가 감사.

3. end-to-end 파이프라인 — 실검증됨

web tool (PushPullTool.ts) │ bridge.* 호출 ▼ WasmBridge.ts (318 메서드, 303 this.engine.<fn> call site) │ marshal Uint32Array / Float64Array / JSON ▼ axia_wasm_bg.wasm (3.63MB, AxiaEngine) │ Half-Edge DCEL mutate ▼ ★ integrity gate — op 전 verify_volume_integrity + boundary + self-intersection baseline 스냅샷 │ if after.damage_count() > baseline → restore_scene_snapshot (byte-identical 롤백) ▼ mesh / delta 버퍼 재읽기 (zero-copy Float32Array view onto WASM linear memory) ▼ Viewport.updateMesh → THREE.BufferGeometry → 렌더

변형 op는 fire-and-forget이 아니다. 틀린 geometry를 내느니 baseline 대비 손상 증가 시 byte-identical 롤백 + 한글 에러. 동일 커널이 headless(axia-wasm-node 3.61MB)로도 도달 가능해 MCP 서버 13 handler를 구동하고, e2e.test.ts가 실제 WASM에 draw_rect→ShapeId·push_pull→audit를 왕복시킨다.

5. ★최대 갭 — 범용 exact/robust CSG는 shipping 엔진이 아니다

  • robust Shewchuk predicates(orient2d/3d·incircle·insphere) 완전 구현 + 14 테스트 — 그러나 production call site 0(predicates/ 내부에서만 참조). production mesh op은 여전히 naive f64 cross product + ε(정점 1e-7 / 면 1e-6 / coplanar 0.1°).
  • 범용 watertight Boolean(solid_boolean)은 test-only — 20개 grep 히트 전부 자기 정의 + boolean.rs 내부 테스트 호출, scene/wasm 호출자 0. production boolean()은 analytic-primitive dispatch + carve PushPull만 처리. 임의 회전/오목/multi-loop 오퍼랜드는 byte-rollback + 한글 에러로 거부(안 풀고). multi-loop 면 명시 거부(boolean.rs:1587).
  • 범용 NURBS surface-boolean은 probe/diagnostic: non-rational only, region당 single closed chain, containment depth ≤1, open-shell surface trim(watertight solid 아님). rational-NURBS SSI 미구현, tensor uv-inversion은 placeholder(0.5,0.5).

"analytic-first, reject-on-damage"가 이 아키텍처의 정직한 심장이다. 마케팅("스케치업보다 정확")은 exact-predicate 견고성을 함의하나, 그 기계장치는 준비돼 있되 shipping 경로가 쓰지 않는다 — 정밀도는 f64+tolerance+불변식 gate로 방어된다.

6. README vs 실제 (양방향 stale)

  • Boolean 과대: 헤드라인 "Union/Subtract/Intersect" — 실제는 analytic + carve만. 웹에 Boolean 도구 파일조차 없음.
  • Import 양방향 stale: SKP를 나열했으나 실제는 hard throw(".skp 직접 import 미지원"). 반대로 STEP·IGES·3DM은 README에서 누락됐으나 실제 동작(opencascade.js / rhino3dm).
  • "스케치업보다 정확": robust predicate 0 call site라, 정밀도 주장은 f64/tolerance로 방어 가능하나 exact-predicate 견고성은 shipping 경로 미사용.
  • Export 비대칭: 11 import vs DXF만 진짜 export. STEP/IGES export는 placeholder Toast.
  • 패널 도킹: README는 Floating/Docked/AutoHide를 나열하나 auto-docking은 사용자 피드백으로 의도적 비활성(기계장치는 코딩됐으나 UX 미도달).

  • wasm/lib.rs boolean_op~8906 — defense-in-depth: baseline 스냅샷 → damage_count > baseline → restore byte-identical 롤백. 아키텍처의 심장.
  • mesh_invariants.rs:188-459 + p7_manifold.rs — I1–I5·M1–M5 ring-with-hole manifold + compute_topology(Euler χ = V−E+F·genus·boundary-loop). 배선된 watertight 검증(장식 아님).
  • carve.rs:496-914 — carve_pocket/through/curved_from_source_face: 실제 local DCEL carving(punch_polygon_hole + no-twist walls + floor cap + 롤백), production PushPull subtract(47 테스트).
  • step_lexer/parser + conic_converter.rs — 무의존 STEP ISO-10303-21 lexer/parser/resolver + Piegl A7.1/A7.4/A7.5 conic→rational NURBS(√2/2 weight). unwired spike지만 깊은 numerics.
  • WasmBridge.ts:27-83 — Cardinal Plane SSOT 스냅 1e-4(0.1μm, 엔진 0.15μm spatial-hash 아래로 튜닝, ADR-147) — 언어 seam의 미묘한 정확성 가드.
  • mcp-server/dispatcher.ts:102 + policy.ts:62 — 5단계 ingress(policy→handler→Zod safeParse→timed call→audit) + fail-closed DENY + Levenshtein "did you mean".

9. axia-sketch(우리 다른 엔진)와의 관계 — 직접 유관

  • 둘 다 XIA lifecycle(Dissolved↔Edge↔Face↔Solid) 개념 공유. AXiA3D = WASM + web + DCEL, axia-sketch = native winit/wgpu + mesh/BREP.
  • ★AXiA3D는 이미 3DM(rhino3dm.js)·STEP(opencascade.js) import가 웹 레이어에서 동작 — axia-sketch 증분6(Rhino import)에서 설계한 "C→spike→A(opennurbs FFI vendor)"의 웹-JS-라이브러리 대안 선례. AXiA3D는 Rust FFI 대신 프론트에서 rhino3dm.js/opencascade.js를 씀.
  • 두 엔진 다 "analytic-first, exact는 미배선/거부" 전략 공유(AXiA3D=robust predicate 미배선, axia-sketch=Track C exact-BREP도 특정 케이스만 배선).

한 줄 요약

E:\AXiA3D는 성숙하고 정직한 production-track 엔진이다. happy path(draw → push/pull → analytic boolean → material → save/load → DXF/OBJ export)는 실동작·조밀 테스트, frontier(임의 solid CSG·foreign-CAD 왕복·Tier-3 AI op)는 gate/deferred. 최대 미완은 범용 exact CSG(predicate는 준비됐으나 미배선)와 foreign-CAD import의 unwired Rust spike(웹은 JS 라이브러리로 우회 동작).

부록 — 검토 방법: 12개 서브시스템을 병렬 리더 에이전트가 각 영역의 lib.rs·mod.rs·최대 파일·테스트를 실제로 열어 조사(구현 vs 부분/스텁/TODO/dead, 테스트 수, file:line 근거) → 종합. 별도로 cargo test로 2,844 커널 테스트 통과(0 실패)·WASM 바이너리 magic·git 활동·ADR 수를 직접 실측해 서베이 주장을 교차검증. 근거 없는 이론적 우려는 배제, 실코드 인용 필수. 편집 없이 읽기·분석 전용.
